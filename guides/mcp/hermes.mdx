Hermes connects to Portfobit's HTTP MCP server with browser-based OAuth.

## Recommended: Install the Portfobit plugin

Paste this into Hermes:

```text
Install and enable the Portfobit plugin in Hermes from https://github.com/portfobit/portfobit-plugin, following https://docs.portfobit.com/guides/mcp/hermes. Use its shared skills and Remote MCP connection, guide me through browser authorization and permissions, then verify the connection with a read-only account query. Preserve existing MCP settings and never request credentials in chat. Then help me connect my first exchange account using https://docs.portfobit.com/guides/connect-your-first-account.
```

Install and enable the Portfobit plugin, then sign in to Portfobit in your browser. On the OAuth authorization page, choose the access you need and approve the connection.

Ask **“Use portfobit to list the account connectors I can connect.”** to check the connection. Installing the plugin does not grant account access by itself. See the [plugin installation guide](https://github.com/portfobit/portfobit-plugin/blob/main/docs/install/hermes.md) for enablement, conflicts and uninstall steps.

If you already configured Portfobit manually, keep a single connection to avoid duplicate tools.

The manual methods below remain available. For remote or headless deployments, use the dedicated Bearer instructions rather than expecting a local browser callback to reach a remote gateway.

## Local interactive install: OAuth

1. Add Portfobit with OAuth authentication:

```bash
hermes mcp add --url https://mcp.portfobit.com/v1/mcp --auth oauth portfobit
```

2. Start the OAuth login:

```bash
hermes mcp login portfobit
```

3. Sign in to Portfobit in the browser and choose the scopes you want to grant.
4. Ask: **“Use portfobit to list the account connectors I can connect.”**

If an existing `mcp_servers.portfobit` entry has a static bearer header, remove it before logging in with OAuth.

## Remote or headless gateway: Bearer

When Hermes runs on a VPS, in a container, or without an interactive browser, keep a dedicated least-privilege Developer API Key in the process environment or `~/.hermes/.env`:

```bash
PORTFOBIT_API_KEY=<PORTFOBIT_API_KEY>
```

Then reference it from `~/.hermes/config.yaml`:

```yaml
mcp_servers:
  portfobit:
    url: "https://mcp.portfobit.com/v1/mcp"
    headers:
      Authorization: "Bearer ${PORTFOBIT_API_KEY}"
```

Here `${PORTFOBIT_API_KEY}` is a Hermes environment-variable reference, unlike the `<PORTFOBIT_API_KEY>` replacement placeholder in the generic JSON example. Store only the raw key in `PORTFOBIT_API_KEY`; the YAML adds the `Bearer` prefix. Keep both files out of source control and revoke the key from **Dashboard → API Keys** when the gateway is retired.
